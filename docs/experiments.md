# Протокол и интерпретация

## Настройки и выбор модели

Стартовое обучение без файла конфигурации задаёт 50 000 исходных шагов среды; `config.json` фиксирует 200 000 шагов для полного протокола. Оба варианта используют 8 сред, 32 решения на фрагмент, повтор действия 20 и проверку каждые 2 обновления. Размер мини-пакета — 64, эпох обновления — 10, скорость Adam — 0,0003; γ = 0,99, λ = 0,95, предел отношения PPO ε = 0,2. Для протокола используйте `config.json` без изменений на всех фазах.

Пилот использует seed обучения 0. Для перехода к подтверждению он должен достичь успеха не менее 90% на трёх последовательных детерминированных проверках валидации. Затем оба подтверждающих запуска, seed 11 и 12, должны пройти тот же критерий. После этого выполняются пять финальных обучений с seed 1–5. Лучшие контрольные точки выбираются по средней награде и затем доле успеха на валидации; отдельная контрольная точка выбирается для видео. Валидация использует 20 seed среды 10000–10019, тест — отдельные 100 seed 20000–20099. Тест не участвует в выборе модели. Все фазы используют одну и ту же конфигурацию и бюджет 200 000; `--resume` пропускает только завершённые совпадающие запуски.

Каждая финальная модель и три базовые стратегии оцениваются на одинаковых тестовых seed. Эвристика направляет тягу по знаку скорости; `random` выбирает равномерное действие на каждом шаге. `random_hold` выбирает равномерное действие в диапазоне среды и удерживает 20 шагов без обучения. PPO также удерживает действие, поэтому его класс политик ограничен; сравнение с базовыми методами отражает разные частоты принятия решений. Среднее и выборочное стандартное отклонение PPO рассчитываются между пятью обучениями, а не между эпизодами. Критерий 90% для отчёта относится к средней тестовой доле успехов пяти обучений. В проведённом эксперименте цель достигнута: 499 успехов из 500 тестовых эпизодов пяти моделей. Модель seed 4 выбрана по валидации и имела 99% успеха на тесте; остальные модели — по 100%. Это результат для фиксированных тестовых начальных состояний. Старые результаты не перезаписаны.

## Как читать показатели

Среда выдаёт +100 при достижении цели и на каждом шаге вычитает `0.1 × action²`. Награда в отчёте — исходная недисконтированная сумма; метрика затрат управления — сумма квадратов действий на исходных шагах (в CSV сохранено имя `action_energy`). Это не физическая энергия. Длина и бюджет тоже измеряются исходными шагами. Для обучения награды внутри решения дисконтируются, следующая ценность умножается на `gamma**k`, а λ применяется один раз на решение. Это не меняет сообщаемую награду среды. Подробнее: [Gymnasium Mountain Car Continuous](https://gymnasium.farama.org/environments/classic_control/mountain_car_continuous/).

Возможная гипотеза при наблюдении почти нулевых действий и нулевой доли успеха: редкая награда за цель может недостаточно часто встречаться во время исследования, тогда как штраф за управление действует постоянно, и политика может предпочесть малые действия. Это объяснение нужно проверять по данным; оно не доказывается одной кривой и не предсказывает исход каждого запуска. Сравнивайте награду, долю успехов, энергию действий и длину эпизода вместе, а также результаты нескольких seed обучения.

Фиксация seed помогает воспроизводимости, но вычисления могут различаться между версиями библиотек и оборудованием.



Сравнение прежнего запуска на 1 миллион шагов с пересмотренным на 200 тысяч не является чистой проверкой одного изменения: изменились повтор действий, длина фрагмента и единица применения λ в GAE. Исторический диагноз и его измерения сохранены в [diagnosis.md](diagnosis.md).


## Расширенная проверка и сравнение частот управления

Исходные модели дополнительно проверены на 1 000 новых начальных состояниях и сетке из 201 позиции. [Результаты и разбор провала](robustness.md). Эти данные считаются диагностическими и не используются как окончательный тест новых настроек.

Отдельный эксперимент `mountaincar.study` сравнивает повтор действия 1, 5, 10 и 20 на общих seed обучения 0, 11 и 12. Каждый запуск получает ровно 200 000 исходных шагов обучения. Параметр `eval_every_updates` равен соответственно 40, 8, 4 и 2: это около 10 240 исходных шагов между проверками при полных фрагментах. Завершение эпизодов сокращает фактический интервал. Такое правило ограничивает различия в числе возможностей выбрать лучшую контрольную точку.

Для допуска конфигурации все три пилотных запуска должны иметь минимум три последовательные проверки с успехом не ниже 90%. Среди допущенных выбирается максимальная средняя лучшая награда на валидации, затем доля успехов, затем меньший повтор при равенстве. Обучение пяти финальных моделей выполняется для выбранного повтора и эталона 20; если выбран 20, это одна группа из пяти моделей. Конкретная модель внутри группы выбирается по валидационной награде, затем успеху и более раннему шагу контрольной точки.

До окончательной оценки сохраняется `frozen.json` с хешами всех финальных контрольных точек и выбранными seed. Только затем каждая из пяти моделей в каждой группе, эвристика и четыре случайные стратегии с соответствующим повтором оцениваются на 1 000 общих отложенных seed 40000–40999. Показатели выбранной модели и среднее со стандартным отклонением между пятью обучениями показываются отдельно. Окончательный набор не используется для настройки или выбора модели.

```powershell
$env:OMP_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
python -m mountaincar.study pilot --resume
python -m mountaincar.study select
python -m mountaincar.study final --resume
python -m mountaincar.study freeze
python -m mountaincar.study evaluate
```

Команды выполняются последовательно из каталога проекта. Пилоты можно выполнять параллельно отдельными процессами с `--seed 0`, `--seed 11` и `--seed 12`, поскольку они пишут в разные каталоги. Общий и ограниченные запуски одновременно запускать не следует. `--resume` принимает завершённый запуск только при совпадении конфигурации, происхождения кода и хешей файлов; несовпадающий или незавершённый каталог сохраняется и вызывает отказ. Перед повторным запуском после прерывания переместите такой каталог в отдельное место. Команды записывают результаты в `results/improvements/study`. Полный эксперимент сравнения пока не завершён; его рабочие результаты исключены из Git. Первоначальные файлы в `results/revised` сохраняются.

Это сравнение вариантов процедуры обучения с разной частотой управления. При фиксированных 32 решениях на фрагмент меняются его длительность в исходных шагах, общее число решений и обновлений, а также временной смысл λ, применяемой один раз на решение. Поэтому результат нельзя приписывать одному лишь повтору действия при всех остальных временных свойствах, оставленных неизменными. Награда среды не меняется; длительность эпизода остаётся дополнительной метрикой.

Для каждого завершённого запуска `budget.json` отдельно считает исходные шаги обучения, решения, обновления и исходные шаги детерминированной и стохастической валидации. `completed.json` хранит хеши конфигурации, исходников и результатов; зависимости фиксируются существующим `requirements.txt`, версии Python, Gymnasium, NumPy и PyTorch записываются в происхождении запуска. Прерванные измерительные запуски помечены `_excluded` и не участвуют в сравнении.
