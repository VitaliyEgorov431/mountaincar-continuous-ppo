# Разбор программы

`agent.py` создаёт отдельные сети политики и ценности. Политика выдаёт параметры нормального распределения; PPO хранит исходное действие и логарифм плотности, а среда получает ограниченное действие. Контрольная точка хранит `action_repeat`; для старых файлов без этого поля используется 1.

`controls.py` выполняет одно решение: удерживает действие до заданного числа исходных шагов, завершения эпизода или ограничения бюджета. Возвращаются дисконтированная сумма наград для обучения, длительность и показатели исходных шагов. Укороченное решение использует фактическую длительность `k`.

`train.py` собирает фрагменты решений в параллельных средах. Для каждого перехода используется `R = sum(gamma**j * r[j])` и множитель `gamma**k` для следующей ценности. GAE применяет `lambda` один раз на решение: `A = delta + gamma**k * lambda * (1-done) * A_next`. При `terminated` загрузка ценности отключается; при `truncated` используется последнее наблюдение до сброса, но рекурсия не пересекает границу эпизода. PPO обновляет политику по сохранённым исходным действиям и старым плотностям. Логи и бюджет измеряются исходными шагами.

`evaluation.py` оценивает детерминированную политику по умолчанию и считает исходную награду, длину, энергию, максимальное положение и абсолютную скорость. Стохастическая оценка изолирует состояние генератора PyTorch. Базовые `random` и `heuristic` выбирают действие на каждом шаге; `random_hold` удерживает равномерную выборку 20 шагов без обучения. `recording.py` записывает каждый исходный кадр с частотой среды.

`experiments.py` проводит явные фазы pilot, confirm, final и report с проверкой фиксированной конфигурации и результатов валидации. `plots.py` строит графики, `__main__.py` разбирает команды. Тесты проверяют вычисления, повтор действия, метрики и ограниченный тренировочный цикл; они не доказывают качество обученной политики.
